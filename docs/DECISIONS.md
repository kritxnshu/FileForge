# Decisions

Every deviation from the build prompt, and every choice where the prompt offered options, is recorded here with its reason.

| # | Decision | Reason |
|---|---|---|
| D1 | **Queue: arq** (Redis-backed, asyncio). Two worker processes, one per queue (`fast`, `heavy`), each with `max_jobs` = `WORKER_CONCURRENCY_*`. | Workers never do conversion work in-process: every job is a sandboxed child process. The worker only supervises (spawn, read progress lines, poll cancel flag, kill process group). An asyncio worker does that for many jobs at once in one process, with no fork() (fork is unsafe on macOS with Objective-C frameworks loaded, which bites RQ). Celery is heavier than needed; Huey has no async supervision. |
| D2 | **Python 3.12** pinned via `uv`. | 3.12 has wheels for every native dependency (pillow-heif, pikepdf, pypdfium2, py7zr, zxing-cpp). Host had 3.14 only. |
| D3 | **Every conversion runs in a child process** (`python -I -m engine.child`) launched by `sandbox.run()`, even pure-Python ones (Pillow, pypdf). CLI engines (ffmpeg, soffice, pandoc) are launched *from inside* that child and inherit its limits, process group and isolation. | One isolation boundary for all parsers of hostile input. Python image/PDF decoders are native code too. |
| D4 | **Local isolation on macOS: Seatbelt (`sandbox-exec`)** with a profile that denies all network and denies file writes outside the job directory. On Linux: bubblewrap if present (`--unshare-net`, read-only binds, job dir writable); otherwise rlimits + timeouts only (logged at boot). Production containers add no-network + read-only rootfs. | The prompt asks for bubblewrap/nsjail locally if available. Neither exists on macOS; Seatbelt is the native equivalent and was verified to block network. |
| D5 | **`RLIMIT_AS` on macOS** is not enforced by the kernel. On macOS the sandbox sets `RLIMIT_DATA`/`RLIMIT_AS` best-effort and relies on timeouts + output-size limits (`RLIMIT_FSIZE`) + Pillow's pixel cap. On Linux `RLIMIT_AS` is enforced. | Platform limitation; documented in SECURITY.md. |
| D6 | **SVG rasterizer: resvg** (`resvg-py`) with an SVG pre-sanitizer (defusedxml parse; any `href`/`url()` that is not `data:` or `#fragment` is removed) and `resources_dir` unset. | resvg does no network I/O and is permissive-licensed (MPL-2.0 / Apache-2.0). The sanitizer additionally prevents local file reads. |
| D7 | **Support levels are earned, not declared.** Each operation declares a *target* level. A pytest plugin records per-pair pass/fail into `services/api/engine/verified.json`; the API advertises a pair only if its latest recorded test passed. | Implements rules 3 and 5 mechanically. |
| D8 | **Client-side tools are registered in the Python registry** with `runtime="client"` (metadata only); their implementations live in `apps/web/src/lib/tools/`. Vitest results are merged into `verified.json` by `scripts/merge_vitest_results.py`. | The UI must never hard-code the list of conversions, including client tools. |
| D9 | **Reverse proxy: Caddy** (dev and prod). `/api/*` → FastAPI, everything else → Next.js. | Automatic TLS in production, one-line config. |
| D10 | **Format detection uses hand-written signature checks** plus container inspection (ZIP/OLE2/ISO-BMFF/RIFF) instead of libmagic. | Fewer native deps, deterministic results across platforms, and we need container inspection anyway. `ffprobe` confirms audio/video. |
