# Decisions

Every deviation from the build prompt, and every choice where the prompt offered options, is recorded here with its reason.

| # | Decision | Reason |
|---|---|---|
| D1 | **Queue: arq** (Redis-backed, asyncio). Two worker processes, one per queue (`fast`, `heavy`), each with `max_jobs` = `WORKER_CONCURRENCY_*`. | Workers never do conversion work in-process: every job is a sandboxed child process. The worker only supervises (spawn, read progress lines, poll cancel flag, kill process group). An asyncio worker does that for many jobs at once in one process, with no fork() (fork is unsafe on macOS with Objective-C frameworks loaded, which bites RQ). Celery is heavier than needed; Huey has no async supervision. |
| D2 | **Python 3.12** pinned via `uv`. | 3.12 has wheels for every native dependency (pillow-heif, pikepdf, pypdfium2, py7zr, zxing-cpp). Host had 3.14 only. |
| D3 | **Every conversion runs in a child process** (`python -I -m engine.child`) launched by `sandbox.run()`, even pure-Python ones (Pillow, pypdf). CLI engines (ffmpeg, soffice, pandoc) are launched *from inside* that child and inherit its limits, process group and isolation. | One isolation boundary for all parsers of hostile input. Python image/PDF decoders are native code too. |
| D4 | **Local isolation on macOS: Seatbelt (`sandbox-exec`)** with a profile that denies all network and denies file writes outside the job directory. On Linux: bubblewrap if present (`--unshare-net`, read-only binds, job dir writable); otherwise rlimits + timeouts only (logged at boot). Production containers add no-network + read-only rootfs. | The prompt asks for bubblewrap/nsjail locally if available. Neither exists on macOS; Seatbelt is the native equivalent and was verified to block network. |
| D5 | **`RLIMIT_AS` on macOS** is not enforced by the kernel. On macOS the sandbox sets `RLIMIT_DATA`/`RLIMIT_AS` best-effort and relies on timeouts + output-size limits (`RLIMIT_FSIZE`) + Pillow's pixel cap. On Linux `RLIMIT_AS` is enforced. | Platform limitation; documented in SECURITY.md. |
| D6 | **SVG rasterizer: resvg** (`resvg-py`) with an SVG pre-sanitizer (defusedxml parse; any `href`/`url()` that is not `data:` or `#fragment` is removed) and `resources_dir` unset. | resvg does no network I/O and is permissive-licensed (MPL-2.0 / Apache-2.0). The sanitizer additionally prevents local file reads. |
| D7 | **Support levels are earned, not declared.** Each operation declares a *target* level. A pytest plugin records per-pair pass/fail into `services/api/engine/verified.json`; the API advertises a pair only if its latest recorded test passed. | Implements rules 3 and 5 mechanically. |
| D8 | **Client-side tools are registered in the Python registry** with `runtime="client"` (metadata only); their implementations live in `apps/web/src/lib/tools/`. Vitest results are merged into `verified.json` by `scripts/merge_vitest_results.py`. | The UI must never hard-code the list of conversions, including client tools. |
| D9 | **Reverse proxy: Caddy** (dev and prod). `/api/*` → FastAPI, everything else → Next.js. | Automatic TLS in production, one-line config. |
| D10 | **Format detection uses hand-written signature checks** plus container inspection (ZIP/OLE2/ISO-BMFF/RIFF) instead of libmagic. | Fewer native deps, deterministic results across platforms, and we need container inspection anyway. `ffprobe` confirms audio/video. |
| D11 | **CSP with a per-request nonce** (`apps/web/src/proxy.ts`): `script-src 'self' 'nonce-…' 'strict-dynamic'`, no `'unsafe-inline'` scripts, no `eval` in production. `style-src` keeps `'unsafe-inline'`. | Scripts are the XSS vector, so they get the strict treatment. React `style` attributes (before/after slider, progress width, colour swatches) can't carry a nonce, and style injection can't run code. Uploaded content is never rendered on this origin anyway. Tested in `tests/e2e/csp.spec.ts`. |
| D12 | **Motion is used only for entrance animations** (file rows, job cards; 200 ms) under `MotionConfig reducedMotion="user"`; everything else is CSS transitions ≤ 250 ms, disabled by `prefers-reduced-motion`. | The prompt asks for restrained motion. Entrance animation is where it helps orientation; elsewhere it would only add delay. |
| D13 | **Background removal is not shipped** (listed as Unsupported). `ENABLE_BACKGROUND_REMOVAL` is reserved. | `rembg` needs onnxruntime plus a ~170 MB model downloaded at run time, which the no-network sandbox forbids; it would have to be baked into the image. Model-weight licences vary (BRIA RMBG is non-commercial), and IMG.LY's library is AGPL. It's the only optional AI feature in the prompt, and shipping it untested would break rule 3. |
| D14 | **OCR via OCRmyPDF with `--output-type pdf`** (Tesseract engine). The `ocr` dependency group is installed by default for development and opt-in in Docker (`WITH_OCR=true`). PDFs that already have text on every page are refused unless "Re-OCR" is on; mixed PDFs are OCR'd only where pages lack text (`--skip-text`). | `--output-type pdf` avoids PDF/A conversion, so Ghostscript (AGPL) is never needed. Running it as `python -m ocrmypdf` from the API's own environment avoids picking up a stray copy on `PATH`. |
| D15 | **Dockerfiles and `docker-compose.yml` are shipped but were not built here.** | The development machine has no Docker (M0 check). The prompt says not to block on Docker. The images mirror the native stack the tests exercise; DEPLOYMENT.md has a go-live checklist that builds and smoke-tests them. |
| D16 | **Valkey instead of Redis in Docker Compose.** Development uses whatever Redis-compatible server is installed. | Redis 7.4+ is RSALv2/SSPLv1 (8.x adds AGPLv3). Valkey is the BSD-3 fork with the same protocol, matching the prefer-permissive policy. |
| D17 | **bubblewrap is probed once at boot**; if it can't create namespaces (Docker's default seccomp profile), jobs run with rlimits + timeouts and the container provides network and filesystem isolation. | Otherwise every job would fail inside a container. `/api/health` reports the mode actually used. |
| D18 | **Graceful worker shutdown.** On SIGTERM workers stop taking jobs and wait `WORKER_SHUTDOWN_GRACE_S` (20 s); jobs still running are then cancelled, cleaned up and marked failed with "The server restarted… Try again." | Before this, a deploy left interrupted jobs showing "running" until they expired. Tested in `test_concurrency.py::test_worker_restart_mid_job_fails_cleanly_with_retry_message`. |
| D19 | **Worker logs name only the exception class** for crashed jobs, not the engine's stderr or the exception message. | Messages and engine output can quote file contents (rule: never log contents). `UC_DEBUG_ERRORS=1` exists for local debugging. |
| D20 | **Accessibility is checked with axe-core** (WCAG 2.1 A and AA rules) on every page type in both themes, plus a keyboard-only journey (`tests/e2e/a11y.spec.ts`). | Automated rules catch contrast, labels, names, roles and landmarks; they can't judge everything (e.g. how a screen reader narrates the flow). That still needs a manual pass with a screen reader before launch. |
| D21 | **`/convert/<a>-to-<b>` for two known formats with no conversion renders an explanation (200, `noindex`)** with links to what that format *can* become. Other unknown paths get a 404 page with next steps. | The prompt asks that picking an unsupported pair gives a helpful message. Links and searches naturally produce such URLs. |
| D22 | **No `docs/ANALYSIS.md`.** | The repository was empty apart from the build prompt at M0 (§4.2), so there was nothing to analyse. |
